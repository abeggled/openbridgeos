# open bridge operating system 2026.10.0

This release establishes the first complete OBOS appliance update path and
consolidates the MVP administration experience.

## Highlights

- Complete appliance updates now cover signed OBOS system files, Debian
  packages, the kernel and container runtime, and configured OBS container
  images.
- The console verifies and displays the latest signed release version and
  release notes before an administrator confirms an update.
- Updates create a consistent OBS backup, verify local and HTTPS health after
  restart, and schedule a controlled reboot when packages, a kernel, or the
  OBOS release require it.
- Onboarding gates OBS access until the local administrator password is set.
- The authenticated console and diagnostics page show appliance health,
  security deviations, technical readiness, bounded support logs, and clearer
  action feedback.
- TLS bootstrap and public Root CA export are automatic. Leaf certificates use
  the configured host identity and primary address, are valid for at most 90
  days, and renew automatically after 47 days.
- MQTT LAN exposure remains opt-in, supports a source CIDR, and surfaces the
  resulting security-baseline deviations.

## Update and reboot behavior

The update runs a noninteractive Debian full upgrade with package removal
disabled, installs only OBOS artifacts covered by the Minisign-signed manifest,
pulls container images, and validates service health. When a reboot is needed,
the appliance reports it to the browser and waits 60 seconds before rebooting.

The pre-update backup covers OBS application data and configuration. It does
not provide an atomic rollback of Debian packages or OBOS system files.

## Release trust

The appliance accepts this release only when `obos-update.manifest` validates
against its pinned Minisign public key and both the update archive and these
release notes match the SHA-256 checksums in that signed manifest.
